Product Requirements Document · Draft

Media Authenticity Verification Platform

Source verification and AI-manipulation signal detection for image, video, and text claims — phased from a bootstrapped MVP to funded Part 1 R&D.

Version0.1Date2026-07-31
StatusDraft — pre-MVP scopingOwnerFounder

Executive summary

The product has two capabilities. Part 2 — source verification traces an image, video, or claim back to its earliest known appearance and cross-references it against published fact-checks. Part 1 — authenticity signals surfaces evidence of AI generation or manipulation (metadata, compression artifacts, pretrained classifiers, VLM-flagged anomalies) without issuing a verdict.

Part 2 is buildable now on existing APIs and open tooling. A durable, defensible version of Part 1 requires a proprietary training corpus we don't have yet — so this roadmap earns that corpus through paying enterprise usage before funding custom-model R&D, rather than building Part 1 first on spec. The executable path starts narrower than the full vision on two axes at once: one media type (image), one customer vertical — not because the rest is wrong, but because that's the smallest thing that produces a real customer and real data.

Problem statement

Five reference cases anchor scope, urgency, and the latency bar this product has to clear:

  • Hong Kong
    2024    Arup engineering firm — a finance employee wired $25M after a video call where every other participant was a deepfake. Validates that enterprise fraud budget already exists and is willing to pay.
  • India
    2018    WhatsApp mob killings — fabricated child-abduction videos triggered real lynchings across multiple states. Validates public-safety urgency in high-forward-volume markets.
  • Slovakia
    2023    Pre-election deepfake audio — released 48 hours before a national vote, spreading faster than it could be verified. Sets the latency bar: a multi-API deep check is not fast enough for the window that matters most.
  • Global
    2023    "Pope in the puffer jacket," fabricated Trump arrest images — both debunked only by ad hoc human skepticism and manual reverse search, no product involved. The gap is often habit and distribution, not detection capability.
  • Israel–Gaza,
    India–Pakistan    Conflict-cycle misinformation — dominant pattern is old media recirculated as new. Squarely a Part 2 problem (source and date), not a Part 1 one (pixel authenticity).

Product overview

Core primitives

Three primitives cover all media types — video is not a separate system, it reduces to the image primitive plus extraction:

PrimitiveDoes
check_claim(text)Fact-check API match + web search for articles discussing the claim
check_image(image)Hash/cache → reverse image search → source extraction → signals panel
crawl(url)Fetch a candidate source page, extract clean text + publish metadata
check_video(video)= keyframe extraction → check_image() per frame + OCR/ASR caption → check_claim()

Segmentation & GTM sequencing

Enterprise fraud / trust & safety first — fastest sales cycle, proven willingness to pay, cloud-API architecture fits without modification. Government second — needs sovereign/on-prem deployment and carries real political exposure (censorship framing); enter only once enterprise references exist to de-risk the sale. Consumer is a perpetual data and brand channel, never the primary revenue line — free incumbents (InVID) and platform-native features (Google) make it a losing lane to lead with.

Phased roadmap

Phase 0 — MVP

Now · bootstrapped

Ship the narrowest provable slice of Part 2, plus a basic Part 1 signals panel, for one image-dominant vertical — cheaply enough to run on founder or angel capital.

In scope
  • Image-only pipeline (no video, no text-claim yet)
  • Hash / cache layer before any paid API call
  • Reverse image search: Vision Web Detection + Bing Visual Search
  • Crawl4AI source-page extraction
  • Provenance timeline output
  • Part 1 signals panel: EXIF, ELA, one licensed HF classifier, OpenRouter VLM anomaly pass
Out of scope
  • Video pipeline
  • Text-claim / Fact Check API integration
  • Custom-trained detection models
  • Sovereign / on-prem deployment
  • Aggregate score or verdict of any kind
  • Consumer-facing UI polish beyond functional

Functional requirements

IDRequirement
FR-1Perceptual-hash every uploaded image before any paid API call; skip the pipeline on a cache hit.
FR-2Query Vision Web Detection and Bing Visual Search; merge and de-duplicate candidate source URLs.
FR-3Crawl4AI-fetch each candidate URL; extract publish date, canonical URL, JSON-LD article metadata.
FR-4Render a provenance timeline: earliest known appearance, subsequent reposts, source notes.
FR-5EXIF extraction and sanity flags — software tag, missing camera fields, timestamp inconsistency.
FR-6ELA heat-map generation for localized edit/splice detection.
FR-7Run one license-checked pretrained HF classifier; store raw score plus score against our own eval set.
FR-8VLM anomaly pass via OpenRouter — itemized findings, never a verdict.
FR-9Combine FR-5 through FR-8 into one signals panel; no aggregate score surfaced to the user.

Success / exit criteria

Pipeline runs end-to-end on real cases from the chosen vertical; 3–5 test cases legible to a non-technical reviewer; ready to hand to the first design partner.

Duration & dependencies

Weeks, not months — integration work, no novel research. Needs: Vision API key, Bing Visual Search key, OpenRouter account, self-hosted Crawl4AI, 1–2 license-verified HF classifiers.

Next

Then

Convert design partners to paying pilots; assemble a traction narrative built on real numbers, not projections.

Scope addition

Success criteria

Phase 2 — Funded expansion

Funded

Deploy raised capital into the Part 1 R&D and coverage expansion deferred throughout this document.

Scope addition

Video pipeline (reusing check_image on keyframes), text-claim pipeline (Fact Check Tools API), sovereign/on-prem deployment track, custom model training on the Phase 0.5–1 corpus, first government conversations using enterprise references.

Success criteria

Video/text parity with image pipeline; first government pilot or RFP response; measurable accuracy gain of the custom Part 1 model over the borrowed HF baseline.

Key riskGovernment political exposure; sovereign-deployment architecture diverges from the cloud-API MVP; detection accuracy is never fully "solved" — communicate honestly, not as a solved problem.
Duration

6–12 months.

Phase 3 — Consumer channel

Ongoing · low priority

Maintain a consumer touchpoint — browser extension or messaging bot — as a brand and data-acquisition channel, not a revenue line.

Success criteria

Steady corpus contribution and brand awareness — explicitly not judged on standalone revenue.

Duration

Ongoing background thread from Phase 1 onward.

Key riskTemptation to over-invest here because it's the most legible "product" to outsiders. Resist — market analysis says this lane is structurally weak.

Cross-phase requirements

  • Data retention — media and derived signals are not retained past the check unless the customer or design partner has consented; consented data is the only source for the future training corpus.
  • Model licensing audit trail — every third-party model (HF or otherwise) logged with license type and commercial-use approval before it ships in any check.
  • Cost and caching controls — hash-based dedup is mandatory in front of every metered API; per-check cost visible and capped from Phase 0 onward.
  • Crawl scope legal review — Crawl4AI targets reviewed against each site's ToS; extraction is for internal matching/analysis, never republication of scraped content.

Glossary

C2PA / CAI
Coalition for Content Provenance and Authenticity / Content Authenticity Initiative — cryptographically signed manifest standard for media provenance.
ELA
Error Level Analysis — compression-artifact technique that flags localized image edits or splices; no ML required.
EXIF
Metadata embedded in image files — camera, software, timestamp — usually stripped on social re-upload.
pHash
Perceptual hash — a fingerprint for near-duplicate detection, used to cache repeat checks before paying for search APIs.
ClaimReview
Schema.org markup used by fact-checkers; what the Google Fact Check Tools API searches.
VLM
Vision-language model — used here for itemized anomaly explanations, not as a calibrated classifier.
Keyframe extraction
Scene-change-based sampling of representative video frames, reducing video to a set of images.
